## Implementation decisions

- Treated M02 as a framework migration before a target-problem content push.
- Put target-problem mechanics specification first because the PDF and extracted images still need
  to be converted into durable written mechanics specs before implementation.
- Documented that both PDF problems include computational solutions that should be used as
  reference material.
- Documented that the Spannrolle/belt-tensioner graphical solution included in the source material
  must be ignored completely.
- Ordered the milestone around architectural dependency gates:
  semantic equations, generalized mechanics model, planar equilibrium solver, diagram/canvas
  framework, Explore mode, beam migration, target problems, and closure.
- Kept the existing beam problems as regression anchors throughout the roadmap.
- Explicitly limited symbolic work to a small expression model and normalizer for M02 beginner
  statics, not a CAS.
- Required target problems to use shared M02 mechanics, solver, diagram, Practice, and Explore
  contracts instead of problem-specific renderers or validators.
- Moved screenshot-based canvas comparison out of M02 into the global backlog because it is too
  early to make it a milestone requirement.

  diagram, and Explore contracts have stabilized.
